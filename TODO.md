## Catalog table

- [ ] **Responsive catalog table.** Since 2026-11-09 the table is narrower: Environment / Access type, Version / Release date and Modality / Format each share a column, one value above the other, in the two lines of a row (the dataset's description sits under its name). Goal: give each value its own column when the window is wide enough, and fall back to the stacked cells when it is not. The same for Years coverage (the year range beside its sparkline, or above it; the heading's title beside its axis, or above it) and Cohort coverage (the size beside its meter, or above it). The Tags column may wrap onto 2 lines when space is short. Three ways to do it:
  - **Table + `flex-wrap` (recommended, no JS).** Each pair, the coverage cells and their headings become wrapping flex rows, and the tag list gets `flex-wrap: wrap`. The automatic table layout shrinks each column between its narrowest width (stacked) and its widest (one line), so the cells wrap only when the table does not fit. Give the paired values a fixed `flex-basis` (e.g. `flex: 1 0 9rem`), so that every row of a column wraps at the same width and the values line up under their labels. Limits: no order in which the columns compact (the browser shares the shortage across all of them); a pair keeps one header cell, not two; the tags cannot be capped at 2 lines (a `min-width` on `.tags`, e.g. 12rem, stops them at about 2).
  - **Grid + `subgrid` + container queries (no JS).** Real columns, every row switches together, and a chosen order (one breakpoint per group, queried on `.table-scroll`). But the breakpoints are fixed widths set by hand, not driven by the data. It also means redoing the sticky first column and header, the row hover, the borders between datasets and the hidden previous versions, and adding ARIA table roles (`display: grid` on table elements can lose their table semantics in some browsers). Ruled out: `repeat(auto-fit, …)` grids inside cells (sized as a single column, so they never go side by side), and Chrome's `scroll-state(scrollable)` queries (they would flip back and forth between layouts, and are Chrome-only).
  - **Table + a colocated JS hook.** It tries the widest layout and compacts one group at a time, in a chosen order, until the table fits, again on resize. The only option that does all of the above; without JS it falls back to the stacked layout.
